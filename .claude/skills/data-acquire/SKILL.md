# /data-acquire — データ調達（1起動＝1タスク）

蓄積中の調達タスク（research_loop/surveys/ の「データ調達タスク」節・BACKLOG の ⏸ 解除条件）
から1件、またはユーザー指定のタスクを完遂する。

## ガードレール（違反不可）

1. **公開・無料・ToS 遵守のソースのみ**（ペイウォール回避・ログイン必須スクレイプ・
   robots 無視は禁止。市場データの再配布制約に留意＝取得物は data/ 配下・gitignore 圏のみ）。
2. **再現可能性**: 手作業ダウンロードで終わらせず、`examples/update_<name>.py` 形式の
   取得スクリプトを残す（update_external.py の流儀＝冪等・追記・検証付き）。
3. **PIT 規律の文書化**: 各データについて「その情報がいつ公知になったか」（公表日・
   アンカー列）を必ず特定し、docs/24 追記に明記。**遡及改訂され得る列は `_displayed` 型として
   非安全マーク**。事後に構成された履歴（例: 現在の一覧表から過去を推定）は PIT 偽装として禁止。
4. **捏造禁止**: 欠損は欠損のまま（補間・推定で埋めない）。検証で数値が原典と合わない場合は
   保存しない。
5. 書き込み先: `data/`（取得物）・`examples/`（取得スクリプト）・`docs/24`（カタログ）・
   `research_ops/acquisitions/`（調達記録）・`research_loop/`（解禁の状態更新）。
   **docs/03・Phase 2 系・invest_system/validation は接触禁止**。
6. git コミットは1回（スクリプト・docs/24・調達記録・BACKLOG 更新。データ本体は gitignore）。

## 手順

1. **タスク選定と文脈**: surveys の調達タスク節＋BACKLOG ⏸ の解除条件を読み、
   1件選ぶ（ユーザー指定があればそれ）。何が解禁されるかを明確化。
2. **出所特定**: 一次ソース（官公庁・取引所・発行体）を優先。URL・形式・更新頻度・
   ライセンス/ToS を確認し、research_ops/acquisitions/ の記録に残す。
3. **取得スクリプト**: `examples/update_<name>.py` を書く（リトライ・冪等・生ファイルは
   `data/<name>/raw/` に保存＝再パース可能に）。
4. **パース＆正規化**: `data/<name>/` に parquet（銘柄コードは J-Quants 形式の5桁文字列に
   正規化・日付は datetime・列名は英スネークケース）。
5. **検証**: 件数・期間・既知の事実との突合（例: 公表報道の件数と一致するか）・
   PIT アンカーの妥当性。結果を調達記録に書く。
6. **配線**: docs/24 の表とセクションに追記。必要なら軽量ローダ（既存モジュールの流儀）。
7. **解禁**: research_loop/BACKLOG.md の該当 ⏸ を ⬜ に戻す（解除条件が満たされた旨と
   データ所在を追記）。IDEAS の該当 I-n には触れない（状態タグは scout/cycle の管轄）。
8. **記録とコミット**: `research_ops/acquisitions/YYYY-MM-DD-<name>.md`（出所・取得日時・
   件数・検証結果・PIT 注意・再現コマンド）→ commit
   `data(<name>): <何を何件・何が解禁されたか>`。
