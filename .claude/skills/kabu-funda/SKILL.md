# /kabu-funda — 総合ファンダメンタル分析（1起動＝1銘柄1本）

「数字を揃える」のは /kabu-dd、「イベントに備える」のは /kessan-preview、
**「企業を理解する」のが本スキル**。データの羅列で終わらせず、各情報を
「事業KPIのどこに・財務のどの行に・いつ現れるはずか」まで翻訳する。

## ガードレール（違反不可）

1. **エビデンス格付けの強制**: すべての知見に [一次]（開示・IR・説明会）/ [報道] /
   [UGC]（SNS・口コミ・掲示板）/ [未確認] のラベル＋日付＋出典URL。
   **UGC は操作され得る**（ステマ・仕手・煽り）前提で、単独では結論の根拠にしない
   （一次/報道と整合して初めて昇格）。
2. **顧客センチメントと投資家センチメントを混同しない**（別節・別結論。
   「製品は愛されているが株は嫌われている」等の乖離こそ知見）。
3. **ToS 遵守**: ログイン必須サイト（OpenWork 等）の壁は越えない（公開部分まで）。
   WebSearch/WebFetch の単発参照のみ＝自動巡回・大量取得をしない（data-acquire と同じ規律）。
4. **裁量レーン**: 出力は `output/kabu/` のみ。SNS/alt データは PIT 不能＝研究・事前登録・
   レジストリの入力に使わない（定型注記）。断定・投資助言をしない（条件付きケースで書く）。

## 手順

### Step 0 土台と焦点
- コード解決（`equities_master.parquet` or EDINET DB search_companies）。
- 直近30日内の `output/kabu/{code}_*.md`（/kabu-dd 産）があれば土台として読む。
  無ければ /kabu-dd の Step 1-2 相当（EDINET DB コア収集＋ローカル定量）を先に済ませる。
- 分析の焦点を1行で宣言（例: 成長の持続性か・転換点の real か・割安の罠か）。
  引数に焦点の指定があればそれに従う。

### Step 1 事業の解像度（一次資料）
- 決算説明会: WebSearch「<社名> 決算説明会 書き起こし」（ログミーファイナンス等）＋
  EDINET DB の search_qa_sections（説明会Q&A）・get_ir_documents・get_text_blocks_structured。
- **言行一致**: get_kg_kpi_track_record で過去のKPIコミットと達成実績を照合
  （経営陣の信頼度は約束の履歴で測る）。
- セグメント×ユニットエコノミクスを1枚に（何を売って、粗利がどこで出て、何で伸びるか）。

### Step 2 ローカル・オルタナティブ（この repo 固有の資産）
- **有報叙述の変化検知**: `data/processed/disclosure_text.parquet` から当該 secCode の
  MD&A/リスク節を年次で並べる。叙述は通常ほぼコピペ（類似度中央値0.95+, docs/45）＝
  **大きく書き換わった年こそ情報**。何がどう変わったかを読む。
- イベント履歴: `data/edinet/large_holdings*.parquet`（大量保有・変更）、
  `tdnet.load_tdnet()` タグ付き開示、`jpx_tostnet.load_tostnet()` 超大口クロスの当該銘柄分。
- ポジショニング: 信用 short_to_long・空売り残高（margin モジュール）、
  あれば `jsf/` の逆日歩＝投資家の偏りと踏み上げ/投げの素地。

### Step 3 Web オルタナティブ（需要・供給・革新の3面。取れた分だけ・各1行の含意付き）
- **需要側**: 会社IRの月次データ、アプリランキング/レビュー（App Store・Google Play）、
  EC/価格.com/Amazon のレビュー傾向、店舗数・客数の報道、検索トレンドを扱う記事。
- **供給・組織側**: 採用ページ・求人検索の件数感（積極採用=投資 or 離職多）、
  従業員口コミの**公開部分**、キーパーソンの就退任報道。
- **革新・競争**: Google Patents で出願傾向、競合の打ち手、業界団体・官庁統計。
- 各項目は「データ → 事業KPIへの示唆 → 財務のどの行にいつ現れるか」の形式で書く。

### Step 4 SNS・世論（UGC）
- **顧客の声**: 製品/サービス名で X（site:x.com 検索等）・レビュー・YouTube・ブログを検索。
  トーンの主因（何が好かれ/嫌われているか）・量感・時系列変化（炎上/バズ）。
- **投資家の声**: Yahoo!ファイナンス掲示板・みんかぶ・株クラの強気/弱気論点。
  「そこで誰も言っていない事実」があれば明記（＝裁量エッジの候補）。
- claude-in-chrome MCP が接続済みなら X・掲示板を直接閲覧してよい（未接続なら検索経由。
  接続を要求しない）。小型株で UGC が乏しければ「シグナル無し」も知見として記録。

### Step 5 統合と出力
`output/kabu/funda_{code}_{YYYYMMDD}.md`:
① 結論1段落（事業の現在地と論点） ② 強気ケース/弱気ケース（各最大3点・全てラベル付き）
③ 財務との整合（alt データが先行指標として財務のどこに現れるはずか）
④ バリュエーションとの整合（現在の株価が織り込むシナリオはどれか）
⑤ **監視KPIリスト**（次回見る具体項目・取得先・頻度）
⑥ 情報品質表（一次/報道/UGC 件数と重要な欠損） ⑦ 定型注記（ガードレール4）。
ユーザーへは①②⑤を1画面で。
