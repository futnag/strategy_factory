# /kabu-screen — 銘柄スクリーニング（1起動＝1条件セット1リスト）

## ガードレール（違反不可）

1. **裁量レーン**: 出力は `output/kabu/` のみ。research_loop/・レジストリに書かない。
2. **スクリーニング≠検証**: リストは着想。戦略として裁くには通常の事前登録経路
   （/research-cycle）しかない、を出力末尾に定型で明記。
3. **流動性・容量を必ず併記**: 各候補に ADV（売買代金）と「¥50万を1日で建てられるか」を
   付す。紙上妙味が執行コストで死ぬのが micro-cap の既知失敗型（docs/48 limit_reversal・
   micro-cap ブリーフィング §3.2）。
4. 候補数は最大20。多すぎる出力はスクリーニングとして失敗（条件を締めて再実行）。

## 手順

### Step 1 条件の構造化
自然言語条件を {ユニバース（市場/時価総額/S33）、財務（成長・利益率・財務健全性）、
バリュエーション、需給（信用/空売り/大株主）、流動性下限} に分解してユーザー向けに1行で復唱。
- プリセット `10x`: `docs/日米小型・マイクロキャップ市場における個人クオンツ・トレーディング：包括的ブリーフィング・ドキュメント.md`
  を実行時に読み、そこにある選別基準（時価総額帯・成長・オーナー経営等）をそのまま条件化する
  （基準をこのファイルに複製しない＝ドキュメントが正）。

### Step 2 一次絞り込み（EDINET DB）
ToolSearch で screen_companies / get_ranking / search_companies_batch 等を一括ロードし、
財務・規模条件で一次リストを取得（上限100件程度に）。

### Step 3 ローカルで裏取りと格付け
インライン python（docs/24 §3.1）で一次リストに付加:
- 直近株価・ADV・52週高値距離（`daily_by_code/` or wide）
- B/M・E/P の S33 内分位（fundamentals + equities_master）
- 信用 short_to_long・空売り残高（margin モジュール）
- モメンタム 12-1（wide adj_close）
条件適合＋流動性で最終スコア→上位N（≤20）。

### Step 3.5 最終候補の Web 検品（必須）
最終リスト（≤20）の各銘柄に WebSearch で直近の特殊事情を確認（TOB/MBO 進行中・
監理/整理銘柄・不祥事・大幅下方修正・上場廃止観測）。該当は表に注記するか理由付きで除外。
数字だけで拾うと「安いのには理由がある」銘柄が混ざるため、この検品は省略不可。

### Step 4 出力
`output/kabu/screen_{slug}_{YYYYMMDD}.md`:
条件の要約 / 候補表（code・社名・S33・時価総額・キー指標・ADV・一言） /
次アクション（深掘りするなら `/kabu-dd <code>`）/ 定型注記（ガードレール2・3）。
ユーザーには上位5件の要点を1画面で提示。

## 運用メモ
- EDINET DB のスクリーンとローカルの数値が食い違ったらローカル（J-Quants）を優先し、
  相違を候補表に注記（外部DBの更新遅延はよくある）。
- 同じ条件の再実行は前回ファイルとの差分（新規入り/圏外落ち）も報告すると便利。
