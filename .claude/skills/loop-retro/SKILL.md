# /loop-retro — ループの振り返り（1起動＝1レトロ）

対象は**戦略でなくループそのもの**。RD-Agent のバンディット・スケジューラの人間ゲート版＝
「次の四半期、どの探索方向に資源を割くか」の提案を作る。

## ガードレール

1. 数値は `examples/loop_retro.py` が計算（K=0・読み取り専用）。
2. 提案はすべて**提案**（PLAYBOOK §B 改訂は cycle の Step 8 経由・§A/K上限は人間のみ）。
3. 書き込み: `research_ops/retro/` のみ。コミット1回。

## 手順

1. 実行: `$env:PYTHONUTF8="1"; .\.venv\Scripts\python.exe examples\loop_retro.py`
2. 解釈の観点（それぞれ1段落・数字を引用して）:
   - **ファネル健全性**: FAIL 続きは正常（基本率）だが、失敗型の分布に偏りはないか
     （同じ型で2度死んでいたら Stage-0/red-team の網の穴）。
   - **学習密度**: H/サイクルが下がってきたら「同じ教訓を買い直している」＝
     探索領域の転換シグナル。
   - **scout 転換**: 検証到達率が低い場合、原因は 昇格基準が緩い / データ待ちが多い /
     cycle が追いつかない のどれか。
   - **K 効率**: 消費 K に対する「意思決定を変えた知見」（採用候補・除外確定・
     データ調達の起点）の量。
   - **領域配分**: 領域別の K 消費と収穫を並べ、次期の配分傾斜を提案
     （例: 「イベント系は H-17 で構造的に不利＝スケジュール型のみに絞る」）。
   - **operator 較正**: 優先規則の閾値（鮮度日数・⬜下限・週次K）の変更提案があれば
     PENDING 行きの提案として書く。
3. `research_ops/retro/YYYY-Qn.md` にレポート → `git add research_ops/` →
   `ops(retro): YYYY-Qn — <主提案1行>` → サマリ。

## 運用メモ
- 頻度: 四半期＋「H 追加が2サイクル連続でゼロ」のとき臨時。
- レトロの提案が PLAYBOOK/HEURISTICS の大規模改訂を要する場合は、必ず人間承認
  （PENDING）を挟む。
