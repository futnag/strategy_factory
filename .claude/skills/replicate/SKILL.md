# /replicate — 論文の忠実複製（1起動＝1論文）

**目的**: 「論文の主張がこのデータで再現するか」を、戦略検証（research-cycle）から分離して
測る。unexpected_forecast の教訓（縮約定義の乖離が符号逆の一因候補になった）への正面回答。

**research-cycle との分業**: 複製＝忠実度の測定（原論文の条件・標本・慣行で）。
戦略認定＝research-cycle（JP向けの取引可能設計・DSR判定）。複製が成功しても
戦略化には別途 cycle の事前登録が必要。逆に「JP日本標本の論文をそのまま検定する」場合は
cycle で足りる＝/replicate は主に (a) 米国等の論文の JP 移植前の忠実確認
(b) 定義の乖離が疑われる場合の precision 複製に使う。

## ガードレール（違反不可）

1. **複製プロトコルの事前凍結**: 実行前に `research_ops/replications/<slug>.md` に
   スペック（下記 Step 1-2）を書き **git commit してから**走らせる（cycle と同じ改竄防止）。
   結果を見た後のスペック変更・セル追加は禁止（乖離の調査は「新プロトコル」として別回）。
2. **K 会計**: リターンを計算するセルは全て registry の専用 scope `repl_<slug>` に
   `log_trial` で記録（グリッド ≤6・予算 ≤8・research-cycle と同じ）。
   記述統計の再現（Step 3）は K=0。
3. **逸脱ログ必須**: データ制約による原論文からの逸脱（フィールド近似・標本差・
   ラグ慣行差）は**実行前に**列挙し、それぞれ「結果への予想される影響方向」を書く
   （C-Z の per-predictor deviation log 方式）。
4. 判定は**忠実度**（複製 t/SR 比・符号・頑健性パターン）であって DSR-PASS ではない。
   複製成功を「戦略が使える」と読み替えない（コスト・執行は cycle の管轄）。
5. 書き込み: `research_ops/replications/`・`examples/repl_<slug>.py`・registry（API経由）。
   docs/03・Phase 2 系は接触禁止。コミットは2回（プロトコル凍結・結果）。

## 手順

### Step 1 スペック抽出（論文全文から・pypdf 利用可）
標本窓／ユニバースとフィルタ（市場・規模・業種除外）／ブレークポイント（NYSE型か等）／
加重（VW/EW）／分位数／リバランス頻度／会計ラグ慣行／シグナルの厳密定義と符号／
headline 数値（複製目標: リターン・t値・表番号）。不明点は「不明」と明記（推測で埋めない）。

### Step 2 プロトコル凍結（≤6セル）
- **headline セル**: 原論文の条件そのまま（データが許す最大忠実）。
- **標準頑健性マトリクス**から選択: {VW ↔ EW}・{±小型（マイクロキャップ除外）}・
  {原標本期間 ↔ ローカル全期間}。HXZ の教訓＝EW×小型でしか生きない結果は複製失敗と同格。
- 記述統計の照合目標（銘柄数・規模分布など論文 Table 1 相当）を数値で書く。
- 逸脱ログ・忠実度の判定基準（例: 複製 t ≥ 原 t × 0.5 かつ同符号で「複製」・
  C-Z ベンチマーク: 複製 t/原 t の傾き 0.88 が良複製の相場）を事前固定。→ **commit ①**

### Step 3 記述統計 fail-fast（K=0）
ユニバース構築だけ先に走らせ、銘柄数・規模構成を論文と照合。大きく合わなければ
**リターンを見る前に停止**（構築バグ or データ非互換＝プロトコルに追記して仕切り直し）。

### Step 4 実行と判定
`examples/repl_<slug>.py` で全セルを1回実行（scope=`repl_<slug>` に log_trial）。
判定: **replicates / partially（セル依存・条件付き）/ fails**。乖離時は
「構築差・標本差・真の非再現」の切り分け仮説を書く（追試は別プロトコル）。

### Step 5 記録とコミット
- `research_ops/replications/<slug>.md` に §結果を追記（headline 対比表・頑健性
  マトリクス・逸脱の影響評価・BACKLOG/IDEAS への含意）。
- IDEAS の該当 I-n 状態更新の提案・BACKLOG 優先度への反映提案（実施は scout/cycle 管轄）。
- **commit ②** → サマリ（複製判定・原論文比・次アクション）。

## 運用メモ
- 使いどころ: scout が拾った高スコア候補のうち「定義が複雑・原論文が米国・数値が疑わしい」
  もの。全候補に使うとK が嵩む＝cycle 前の保険としては red-team（K=0）を先に。
- 初回 E2E は未実施（最初の実使用がそのまま E2E＝候補: I-45 ライフサイクル（米国・
  方向未固定＝複製で JP 方向を測ってから cycle 化する典型例）。
