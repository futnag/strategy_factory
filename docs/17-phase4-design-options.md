# 17. Phase 4 設計判断（選択肢・既定・影響度）

**機構は実装済み（config 可変）・既定は保守側**で置き、最終決定はユーザーが下す。定量影響は
プリフライト報告（docs/16）、符号規約・重複対応は docs/18 を参照。全工程 **K 不変・判定なし・PIT 厳守**。

> 保守的既定を仮置きし、必要時に切替（config）。

## 1. 投資可能ユニバース ✅ 決定＝流動本番＋全上場診断

- **決定**：本番ユニバース＝**株価 ≥ ¥100・時価総額 ≥ ¥10B・60日 ADV ≥ ¥50M**（普通株のみ・全て PIT）。
  診断（docs/16）は**常に全上場**で回し、除外銘柄の影響を測る。`universe.liquid_universe_mask`。
- **選択肢と影響度**：
  - (採用) 流動本番＋全診断：GKX の小型偏在シグナルを一部捨てるが**実約定可能性・コスト現実性**を確保。
  - 上位500のみ：最簡・大型偏重＝**小型の予測力を捨てる**（過去診断は上位500基準）。
  - 全上場（微小含む）：**最大シグナルだが実現益がコストで削れる**（薄商い約定不能）。
- **取引コスト前提**：既存 `engine.backtest` の片道コスト＋`capacity_jpy`（ADV×参加率で規模上限）を流用。
  小型ティルトを最終採用する場合はコスト感度を別途。**閾値は事前固定（探索しない）**。

## 2. ラベル / ホライズン ✅ 決定＝月次・1M・超過

- **決定**：月次リバランス・**1か月フォワード・ユニバース平均に対する超過リターン**・
  **close[t]→close[t+1]**（建玉 t→実現 t+1）。リターンは §3 のトータルリターン。
- **影響度**：年次ファンダは月次で弱い（docs/03 の既知事項）が、価格/流動性因子と整合する月次が
  クロスセクション ML の標準。超過（ユニバース平均控除）で市場ベータを除き純クロスセクションを学習。
- **代替**：四半期/週次は今回不採用（四半期＝ファンダ整合だがサンプル減、週次＝価格因子寄りでノイズ増）。

## 3. リターン定義（価格 vs トータル） ✅ 決定＝トータル正準

- **決定**：**配当込みトータルリターンを Phase 4 ラベルの正準**。価格リターンは診断比較用に保持。
  `panel.total_forward_returns(adj_price, raw_price, dps)`：AdjC 価格フォワード ＋ 実績年間 DPS
  （fins_summary `DivAnn`・as-of）/12 / 生終値 の配当利回り寄与（PIT）。
- **影響度（docs/16 §で定量）**：日本株の平均配当利回りは概ね 2% 前後＝**高配当銘柄の相対評価が
  価格のみより改善**し、配当利回り因子との二重計上/歪みも整理される。価格 vs トータルの IC・
  リターン差は docs/16 を参照。
- **限界**：DPS は年額を月次均等計上（ex-date 厳密配賦はしない）＝月次の配賦は近似。累積トータルは整合。

## 4. マクロ状態変数の PIT（検討・既定＝公表ラグ厳守）

- **論点**：特性×マクロ交互作用（例：value×金利局面）を使うなら、CPI 等マクロの**公表ラグ**を
  厳守しないと「マクロ先読み」になる（指標日 ≠ 公表日）。`flows.py`（投資部門別）も状態変数化候補。
- **既定（保守）**：マクロ系列は**公表日でアンカー**（指標の対象月でなく実公表日 ≤ t）。公表日が
  無い系列は**1か月ラグを既定**で課す。投資部門別フローは週次・T+? 公表ラグを点検して状態変数化。
- **選択肢**：(a) 公表ラグ厳守＋ラグ不明は保守ラグ（採用候補）／(b) マクロ交互作用を使わない
  （最も安全・表現力は落ちる）／(c) 対象月アンカー（**非推奨＝先読み**）。
- **要ユーザー確定**：マクロ交互作用を Phase 4 に含めるか、含めるならラグ規約。

## 5. S33 セクターの sector-PIT（検討・既定＝スナップショット許容）

- **論点**：`sector_neutralize` 等で使う S33 は **master の現スナップショット**（履歴なし・docs/16 §7）。
  過去のセクター所属が現在と違う銘柄は、厳密には sector の先読み混入。
- **既定（保守）**：**現スナップショット S33 を許容し文書化**（業種は概ね安定で影響小・実装容易）。
- **選択肢**：(a) スナップショット許容＋明記（採用候補・低コスト）／(b) listed_info 履歴/
  edinetdb で S33 を PIT 化（厳密・取得コスト）／(c) セクター中立を使わない（情報損）。
- **要ユーザー確定**：sector-PIT を厳密化するか（コスト次第）。影響は限定的と推定。

## 6. 重複因子の Phase 4 採用方針（docs/18 と一体）

設計行列の列は docs/18 の重複表に従い一意化する（既定の採用候補）：
- **accruals**：EDINET 版（生ライン由来）を採用、J-Quants 版は不採用（**符号が逆**＝混在厳禁）。
- **CF/P**：一本化（`cf_to_price`≡`cf_yield`）。`fcf_yield`/`fcf_yield_3y` は CFI 込みで別物＝残す。
- **モメンタム/Amihud**：12-1 は `factors.momentum` に一本化、Amihud は price_factors の1本（材化済）。
- **成長軸**：`asset_growth`（資産・EDINET）と `equity_growth`（自己資本・JQ）は別軸として両立可。
- **株数**：mcap/回転は J-Quants `ShOutFY−TrShFY`、希薄化は EDINET 分割調整株数＝役割分担。
