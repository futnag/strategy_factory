# 因果的レジーム検知レポート（オンライン・PIT）

**作成日**: 2026-06-23
**診断**: `examples/diag_causal_regime.py`（使い捨て・**K不変・判定なし**・オフライン・APIキー不要）
**対象**: TOPIX 月次（2016-07〜2026-06）。docs/27 の事後“真の”転換点（2018-10 / 2020-03 / 2020-12 / 2022-09）に対し、**各時点 t で ≤t のみを使うオンライン検知器**の**検出ラグ**と**誤警報**を測る。

> docs/27 は全期間を見て当てる**事後**分析（先読みあり）。本レポートは「**生運用でその時点で気づけたか**」を検証する。

---

## 1. 結論（要旨）

- **ボラ・暴落型レジーム（COVID 2020-03、2018-10）は因果検知でも速い**：実現ボラ三分位・ドローダウン・CUSUM(平均) が**ラグ 0〜1 か月**で捕捉。ボラ・スパイクは「大きく・即時」だから。
- **遅い“因子プレミアム回転”（2022-09 value 復権）は因果検知が苦手**：精度の高い検知器（CUSUM 平均・BOCPD）は**見逃し**、感応的な検知器（マルコフ・フィルタ）は **+0〜+9 か月**で“当てる”が**誤警報20回超**に埋もれる。
- **精度⇄感度のフロンティアが厳しい**：誤警報ゼロの CUSUM(平均) は大事件しか捕らえず遅い断層を見逃す。捕らえる検知器は 10年で 11〜21 回の誤警報を伴う。**“速く・clean に 2022 型断層を出す”因果検知器は存在しなかった。**
- **含意**：value+PEAD の成否を決める断層（2022 の回転）は、まさに**因果検知が間に合わない／騙されやすい**種類。＝レジームは*当てる*より*生き延びる*が妥当（docs/26・27 を補強）。

## 4. 主要所見

### 4.1 暴落型 vs 漸進型で検知能力が真逆
- **COVID（2020-03）・2018-10**：ボラ系（C1）・DD（C5）・CUSUM 平均（C2）が**ラグ ≈0**。市場水準の急変＝ loud event なので因果でも即捕捉。
- **value 復権（2022-09）**：CUSUM 平均・CUSUM ボラ・BOCPD・DD は**すべて見逃し**。これは TOPIX 水準・ボラの大事件ではなく、**因子プレミアムの静かな回転**だったため、市場水準の検知器に映らない。

### 4.2 精度⇄感度のトレードオフ（フリーランチ無し）
- **CUSUM(平均)＝誤警報 0** だが、捕らえるのは大事件 2 つ（2018-10・2020-03）のみで**遅い断層は見逃す**。
- **マルコフ・フィルタ／ボラ三分位／DD** は遅い断層も“当てる”が、**誤警報 18〜21 回**。実運用なら**ホイップソー**地獄。
- ＝「2022 型の回転を、速く・誤警報少なく出す」因果検知器は本バッテリには無かった。

### 4.3 フィルタ（因果）vs 平滑（事後）のラグ（C3）
- **平滑（事後）**：波乱突入を 2018-10 / 2020-02〜03 / **2022-09** と clean に提示。
- **フィルタ（因果）**：COVID 突入が **2020-07＝底から約4か月遅れ**、かつ 20回超の突入でガタつく。
- ＝「**平滑は綺麗に見えるが、それは未来を使っているから**。因果フィルタは遅く・ノイジー」という教科書的事実を実データで確認。

## 5. value+PEAD・メタゲートへの含意

- メタゲートが学習・適用したのは**月次・市場/自己状態の局面特徴**。本結果は、その種の信号で**2022 の value 回転を“その時点で”捉えるのは構造的に困難**（速い検知＝誤警報まみれ／clean な検知＝見逃し）を示す。
- ＝**たとえ“良い”因果レジーム検知器を積んでもメタゲートは救えない**。value の優劣を決める回転は、確認できた頃には大半が終わっている。
- 一方で **COVID 型のボラ事件はラグ≈0 で因果検知できる**。だから因果検知の正しい用途は **factor-timing ではなく risk control**（暴落時のエクスポージャ縮小・ボラターゲティング）＝予測でなく防御。

## 6. 限界・次の手

- 市場水準（TOPIX）での検知。**因子水準の因果検知**（例：value LS リターンに CUSUM/BOCPD）なら 2022 回転をもう少し捉え得るが、(a) キャッシュに B/M 値パネルが無く本診断では未実施、(b) これは実質メタゲートの `value_trail` 特徴が試したことと同じで、**同じデータ希少（独立サイクル ~1–2）の壁**に当たる。
- “真の”転換点自体が docs/27 の事後判定＝評価の基準にも先読みが含まれる（ラグの絶対値はあくまで目安）。
- 改善余地：複数検知器の**合議（k-of-n）でホイップソー抑制**、ボラ系は risk-overlay 専用に限定。ただし factor-timing の認定は依然非現実的。
