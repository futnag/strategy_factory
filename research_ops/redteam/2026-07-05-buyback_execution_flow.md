## 最重要指摘（3件・実データ確認済み）

### ①【致命訂正・H-8】BACKLOG の「TDnet タイトルのみ」は不成立＝ローカル TDnet は6週間しかない
BACKLOG は「TDnet 一覧のタイトルで執行月を firm-month 特定」と記載。だが実測:
- `data/tdnet/` は **29ファイル・2026-05-26〜2026-07-03（~6週間・8,295行）**＝前向き蓄積の履歴極浅。
  → **TDnet ベースの歴史的イベントスタディは不可能**（6週間では forward-return 検定にならない）。
- **正しいデータ源 = EDINET「自己株券買付状況報告書（法24条の6第1項）」**（自社株買いプログラム実行中の
  月次規制開示）。`data/edinet/list/`（2016+・2,610ファイル）に docDescription で存在確認済み。

### ②【最重要・F9/H-4/F2】EDINET でも局所履歴は 2025-01+ の ~18ヶ月のみ＝現レジーム内限定
`自己株券買付状況報告書` の局所 EDINET list 収録を年次計数（K=0・実測）:

| 年 | 買付状況報告書 | list 総行 |
|---|--:|--:|
| 2016-2024 | **0** | 55k-95k/年 |
| 2025 | **3,568** | 83,350 |
| 2026 | **3,050** | 35,930 |

- 2016-2024 が全て 0（55k-95k 行/年あるのに）＝**バックフィルがこの doc type を歴史的に除外**（実在しないのでなく未収録）。
- ∴ ローカルの実効履歴 = **2025-01〜2026-07 の ~18ヶ月・~6,600 filings**。
  - **breadth は可**（~370 firm-execution/月＝月次 XS の横断幅は十分・H-12 は満たす）。
  - **だが時間軸が ~18 月次断面のみ＝(a) minTRL 的に認定不能（H-4）(b) 全期間が 2024+ 現レジーム内
    ＝OOS 分離もサブ期間頑健性も取れない（F2）＝「効果」と「現レジーム固有アーティファクト」を識別不能**。
- **修正案**: §2.6 を「認定でなく執行フロー機構の実在判定（現レジーム内・mechanism-detection）」に。
  正しく powered な検定には **EDINET 自己株券買付状況報告書 2016-2024 のバックフィル**（data task・doc type 指定で
  取得可能＝filings は EDINET に実在）が前提＝それ無しなら「18ヶ月・in-regime のみ」の限定結論と正直に記す。

### ③【設計・H-16/F7】発表軸(❌)との識別＋同時性の除去を prereg で固定
- **F7 差別化**: 既試 shareholder_return（発表ドリフト❌ DSR0.24・PBR改革後反転）と**同一に見られない**設計が必須。
  本件は「取締役会決議＝発表」でなく「月次買付状況報告＝実執行」がシグナル。統制セル（**発表済みだが当月執行報告
  なし** vs **当月執行報告あり**）を H-18 で同梱し、「執行フローの増分」だけを検定。
- **H-16 同時性**: 当月の買付は当月リターンと同時（買いが上昇の一因）＝**forward 必須**
  （執行報告 firm-month t → **t+1** リターン＝プログラム persistence を利用・当月リターンは使わない）。
- **H-15/F6**: Clarke は米＝JP 方向は「執行 persistence（複数月の価格非感応な大口買いの継続）」で防御・要事前固定。
  買戻アノマリーは国際的に弱い（MPW）＝gross でも薄い事前分布。

### PIT リーク狩り
- シグナル = 買付状況報告書の submitDateTime（提出時刻ローカル）＝PIT。secCode→ticker、periodStart/End で
  執行対象月を確定。**forward（t+1）執行**＝当月リターン不使用（H-16）。ユニバースは PIT。

### Stage-0 K=0 キル（実行前必須）

  サイズマッチ）を18断面で算出。平均が ~0 or 負なら shareholder_return と同断＝**K=0 で棄却**。
  （パラメータグリッドなしの単一記述＝K 外。）
